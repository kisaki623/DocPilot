# 需要做到的方面

对于这个 **会话级上下文管理系统 / Agent Memory Mode**，我建议主要拆成这些方面来设计：

## 产品模式设计

也就是用户看到的模式是什么：

```Plain Text
RECENT_TURNS 标准模式
AGENT_MEMORY 记忆模式
是否创建对话时选择
是否允许升级
是否允许切换
模式说明如何展示
```

---

## 数据模型设计

要设计哪些表、字段、状态：

```Plain Text
conversation
conversation_message
conversation_summary
user_memory
knowledge_base binding
context_mode
memory status
```

---

## 上下文拼接策略

决定每次请求到底给模型传什么：

```Plain Text
最近几轮消息
会话摘要
长期记忆
知识库 RAG evidence
系统 prompt
当前问题
token 预算
优先级顺序
```

---

## 会话摘要机制

解决长对话不能全塞 prompt 的问题：

```Plain Text
什么时候生成摘要
摘要覆盖哪些消息
摘要如何更新
摘要是否可查看
摘要失败怎么办
摘要和最近多轮如何组合
```

---

## 长期记忆机制

解决跨会话保存用户偏好和项目状态：

```Plain Text
记什么
不记什么
用户手动保存还是自动抽取
记忆分类
记忆删除
记忆冲突
记忆注入数量限制
```

---

## 知识库绑定与 RAG 融合

让 Agent Memory Mode 能结合文档资料：

```Plain Text
一个会话是否绑定 knowledgeBaseId
什么时候触发 RAG
什么时候只用最近多轮
RAG evidence 如何和 memory 一起拼 prompt
知识库权限如何校验
```

---

## 权限与隐私边界

这个是面试重点：

```Plain Text
用户只能访问自己的 conversation
用户只能访问自己的 memory
用户只能绑定自己的 knowledgeBase
敏感信息不默认保存
memory 可查看 / 删除
deleted memory 不再注入 prompt
```

---

## Token 预算与上下文优先级

防止 prompt 越来越长：

```Plain Text
最近消息保留多少
summary 最多多少 token
memory 最多注入几条
RAG evidence 最多几条
超长时谁先被截断
```

---

## 上下文构建服务设计

也就是核心后端服务怎么抽象：

```Plain Text
ContextAssemblyService
ContextPolicy
RecentTurnsContextBuilder
AgentMemoryContextBuilder
MemorySelector
ConversationSummaryService
```

---

## API 设计

前后端如何交互：

```Plain Text
创建会话
发送消息
选择 contextMode
保存 memory
查看 memory
删除 memory
绑定 knowledgeBase
查看当前会话使用了哪些上下文
```

---

## Trace / 可观测性设计

让用户和面试官能看懂系统用了什么上下文：

```Plain Text
本轮使用了几条 recent messages
是否使用 summary
注入了哪些 memory 摘要
是否触发 RAG
命中了哪些文档
token 估算
```

---

## 测试设计

保证这套系统不会乱：

```Plain Text
RECENT_TURNS 只带最近多轮
AGENT_MEMORY 注入 summary + memory
不同用户 memory 隔离
deleted memory 不注入
绑定别人的知识库失败
RAG 权限不绕过
token 超限时正确裁剪
```

---

你后面可以按这个顺序一个个讨论：

```Plain Text
1. 产品模式
2. 数据模型
3. 上下文拼接
4. 摘要机制
5. 长期记忆
6. RAG 融合
7. 权限隐私
8. token 预算
9. API
10. 测试
```

我建议先从 **产品模式设计** 开始，因为它会决定后面数据表、API 和上下文拼接怎么做。
