# 12\.测试设计

开始 **12\. 测试设计**。

这一节的核心是：

> **验证会话级上下文管理系统不会乱拼 prompt、不会越权、不会注入 deleted memory、不会无限撑爆 token、不会让 RAG 绕过权限。**
>
>

你前面的路线里已经把测试重点定成：RECENT\_TURNS 只带最近多轮、AGENT\_MEMORY 注入 summary \+ memory、不同用户 memory 隔离、deleted memory 不注入、绑定别人知识库失败、RAG 权限不绕过、token 超限时正确裁剪。

---

# 测试目标

这个系统的测试不是只测 API 能不能通，而是要测 6 件事：

```Plain Text
1. 模式正确：RECENT_TURNS / AGENT_MEMORY 行为不同
2. 拼接正确：summary、memory、recent turns、RAG evidence 顺序正确
3. 权限正确：不能读取别人的 conversation / memory / knowledgeBase
4. 裁剪正确：超 token 时按优先级裁剪
5. Trace 正确：记录用了哪些上下文，但不泄露完整 prompt
6. 降级正确：summary 失败、RAG no-evidence、trace 写入失败都不能影响主流程
```

一句话：

> **测试要证明：系统能用、可控、安全、可解释。**
>
>

---

# 测试分层

我建议按 5 层测试。

```Plain Text
1. Unit Test：单个组件逻辑
2. Service Test：核心上下文构建链路
3. Controller Test：API 参数、权限、响应格式
4. Security / Scope Test：越权和隐私边界
5. Smoke / Scenario Test：模拟完整用户场景
```

不要所有东西都用 SpringBootTest。

能单测的尽量单测，这样快、稳定、不依赖环境。

DocPilot 的环境边界也明确说：本地单元测试不应该强依赖远程服务器，敏感信息如 `.env`、API key、SSH 信息、数据库密码不应上传。
所以测试里不要调用真实 LLM、真实 embedding、真实 Qdrant、真实远程 MySQL。

## 3\.6 TokenBudgetManagerTest

这是关键测试。

覆盖：

```Plain Text

```

# 面试怎么讲？

你可以这样讲：

> 我把测试分成组件测试、服务测试、API 测试、权限隔离测试和场景 smoke。组件层主要测 ContextPolicy、MemorySelector、TokenBudgetManager、PromptRenderer 和 ContextTraceBuilder；服务层测 ContextAssemblyService 在 RECENT\_TURNS 和 AGENT\_MEMORY 下的不同拼接结果；权限测试覆盖用户不能读取别人的 conversation、memory、summary 和 knowledgeBase，deleted memory 不会注入 prompt；RAG 融合测试保证 Agent Memory Mode 触发知识库检索时仍然复用 KnowledgeBaseScopeGuard，不绕过原有 RAG 权限边界。Trace 测试则保证只返回 memoryCount、summaryUsed、ragTriggered、token 估算等脱敏摘要，不暴露完整 prompt 或敏感信息。
>
>

# 一句话定方案
