# 会话级上下文管理系统

我建议给它的准确定义是：

> **会话级上下文管理系统**
> 英文可以叫：**Conversation Context Management**
> 产品能力名可以叫：**Agent Memory Mode**
>
>

不要直接把整个功能叫“记忆系统”，因为你现在设计的不只是“记住东西”，而是包含：

```Plain Text
会话模式选择
最近多轮上下文
会话摘要
长期记忆
知识库绑定
RAG evidence 注入
token 成本控制
权限隔离
```

所以更准确的是：**上下文管理**，其中“记忆”只是它的一部分。

---

## 我推荐的命名层级

### 大模块名：会话上下文管理

```Plain Text
Conversation Context Management
```

这是最准确的工程定义。

它解决的是：

```Plain Text
一次回答应该带哪些上下文？
带最近几轮？
要不要带摘要？
要不要带用户记忆？
要不要检索知识库？
怎么控制 token？
怎么避免旧上下文污染？
```

---

### 子能力 1：上下文策略

```Plain Text
Context Mode / Context Policy
```

包括：

```Plain Text
RECENT_TURNS
AGENT_MEMORY
```

也就是你说的“最近多轮”和“Agent 记忆模式”。

---

### 子能力 2：Agent Memory Mode

```Plain Text
Agent Memory Mode
```

这是产品亮点名。

它不是整个模块，而是其中一个增强模式：

```Plain Text
最近多轮
+ 会话摘要
+ 用户显式长期记忆
+ 绑定知识库 RAG evidence
```

---

### 子能力 3：长期记忆

```Plain Text
User Memory / Long-term Memory
```

这个只负责保存用户显式记住的内容，比如：

```Plain Text
用户偏好
项目状态
任务目标
回答风格
```

---

## 所以你现在到底在做什么？

最准确地说：

> 你现在是在做 **DocPilot 的会话级上下文管理能力**，其中包含一个增强模式叫 **Agent Memory Mode**。
>
>

不是单纯“会话功能”，也不是单纯“记忆系统”。

更完整的定义是：

```Plain Text
为 DocPilot 设计会话级上下文管理机制，支持 RECENT_TURNS 和 AGENT_MEMORY 两种上下文策略。默认使用最近多轮上下文保证低成本和稳定性；Agent Memory Mode 会额外组合会话摘要、用户显式长期记忆和绑定知识库 RAG evidence，用于长任务连续协作。
```
